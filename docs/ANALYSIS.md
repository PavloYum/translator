# Анализ ТЗ v0.1

> Актуализация 24.11.2026: пользователь выбрал личное использование.
> Коммерческие требования исходного ТЗ (OTP, подписки, лицензии, 72-часовой
> офлайн-доступ, платежи и тарифные квоты) не входят в личную версию.
> Для пилота: Tailscale и отзывной токен приложения; технические лимиты нагрузки
> и расходов API остаются. Разделы ниже о коммерческих механизмах сохранены
> как анализ исходного ТЗ, не как обязательства реализации.

## Вывод
Проект технически реализуем по частям. ТЗ описывает несколько самостоятельных
продуктовых функций, а не небольшой MVP. Ни время отклика, ни поддержка конкретных
наушников, ни экономическая модель ещё не подтверждены экспериментом.

## Что оставить
Kotlin/Compose, AudioRecord, foreground-service для пользовательской аудиосессии,
Room/DataStore, один TranslationEngine, отдельные интерфейсы STT/MT/TTS/LLM,
Python/FastAPI как шлюз, PostgreSQL, Docker ARM64. Pi не следует использовать для
тяжёлого распознавания нескольких клиентов одновременно без измерений. Redis
нужен при нескольких worker-процессах/общих лимитах; на старте допустим один worker.

## Что уточнить до реализации
1. **Фоновый микрофон.** Запускать с видимого экрана по действию пользователя,
   затем продолжать в foreground-service с уведомлением и кнопкой остановки.
   WorkManager не предназначен для непрерывного захвата. Разрешение microphone
   само по себе не разрешает произвольный запуск из фона. Проверять блокировку
   экрана, отказ разрешений, энергосбережение HyperOS, звонки и смену аудиомаршрута.
2. **Наушники.** BLE-поиск и аудиомаршрутизация — разные подсистемы.
   Обычные Bluetooth-наушники не обязаны предоставлять BLE-команды звонка, заряд
   каждого наушника или постоянный MAC. В кейсе устройство может не рекламироваться.
   RSSI — приблизительная близость, не расстояние. «Последняя точка» — координаты
   телефона с временем и точностью, а не достоверные координаты наушника.
   Требуется модель и проверка доступного GATT/SDK; универсальный ring не обещать.
3. **Разрешения BLE.** Список разрешений зависит от Android, targetSdk и использования
   геопозиции. Не запрашивать background location в базовом переводчике; только
   для отдельно включаемой функции. Проверять политику и API перед сборкой.
4. **Офлайн.** ML Kit переводит текст, не речь; RU↔DE может идти через английский.
   whisper.cpp/sherpa-onnx — кандидаты, не взаимозаменяемые готовые решения.
   Для APK измерить RAM, размер пакетов, скорость, нагрев, батарею и лицензии моделей.
   Системный TTS не гарантирует установленный офлайн-голос. 4 ГБ — не гарантия скорости.
   Пользовательские пакеты и пакеты, которыми управляет ML Kit, имеют разные модели
   загрузки: не обещать собственный SHA-256/докачку для непрозрачного SDK-кэша.
5. **Задержка.** Уточнить точку отсчёта partial (начало речи/первый кадр) и конца
   фразы (реальная пауза/VAD). Отдельно измерять VAD, STT, MT, TTS и сеть.
   Цели 0,6/2/3 с считать критериями эксперимента, не гарантией. Partial-перевод
   может изменяться: озвучивать только стабилизированные сегменты.
6. **Обрыв связи.** Порог офлайн 5 с против буфера 10 с требует явной политики:
   не обрабатывать одну реплику локально и в облаке дважды; отменять старый TTS.
   Не включать офлайн без готовых моделей. Утрата серверного буфера — явный reset,
   а не ложное обещание продолжить с прежнего места.
7. **Лицензии.** Хэш сертификата, присланный клиентом, не доказывает подлинность APK.
   R8 — усложнение анализа, не защита от обхода. Device ID не должен быть IMEI/MAC.
   Офлайн-токен привязать к ключу установки; учитывать перевод часов и перезагрузку.
   Немедленный отзыв лицензии офлайн невозможен. exp ограничить одновременно
   сроком лицензии и 72 часами после выдачи. Не блокировать экспорт личной истории.
8. **Приватность.** Есть противоречие: история на телефоне и синхронизация по желанию,
   но в конце ТЗ серверное хранение 30 дней по умолчанию. Предлагается серверное
   хранение текста выключить по умолчанию; 30 дней применять только после согласия.
   Память pipeline также содержит аудио: очищать после обработки, отключить body-логи.
   Согласие участников в интерфейсе — не доказательство согласия каждого человека.
9. **Эксплуатация.** Собственный Pi и интернет — единая точка отказа. TLS/WSS через
   существующий туннель подходит для шлюза; reconnect обязателен. Не менять общие
   сети/Compose других проектов. TURN для будущего VoIP требует отдельного сетевого
   решения; обычный HTTP Cloudflare Tunnel его не заменяет.
10. **Стоимость.** Считать отдельно минуту STT, MT/LLM-токены, TTS, email OTP и трафик.
    PCM16 16000 mono: 32 000 байт/с ≈1,92 МБ/мин только входящего аудио, без overhead.
    TTS 24 кГц: 48 000 байт/с во время речи. Тарифы не выбраны, точная цена неизвестна.
11. **Обновления.** SHA-256 из неподписанного манифеста не защищает подмену сервера.
    Подписывать манифест, проверять APK signer/package/version, защищать от downgrade.
    Хранить release-ключ отдельно; разрешение установки запрашивать при обновлении.
12. **Обычные звонки.** Не включать их захват в MVP. Громкая связь не гарантирует
    одновременный доступ стороннего приложения к микрофону и пригодное качество.

## Проверенные первичные источники (23.11.2026)
- Android foreground microphone restrictions:
  https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start
- ML Kit Translation, языки и ограничения перевода через английский:
  https://developers.google.com/ml-kit/language/translation
- Android developer verification, актуальные этапы и региональные условия:
  https://developer.android.com/developer-verification

Перед публичным APK отдельно перепроверить региональные условия верификации:
не трактовать календарь из черновика как всеобщий запрет установки вне Play.
Юридическое заключение по записи встреч не выполнялось.
