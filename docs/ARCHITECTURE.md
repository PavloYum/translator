# Архитектура — предложение

> Актуализация 24.11.2026: пользователь выбрал личное использование.
> Коммерческие требования исходного ТЗ (OTP, подписки, лицензии, 72-часовой
> офлайн-доступ, платежи и тарифные квоты) не входят в личную версию.
> Для пилота: Tailscale и отзывной токен приложения; технические лимиты нагрузки
> и расходов API остаются. Разделы ниже о коммерческих механизмах сохранены
> как анализ исходного ТЗ, не как обязательства реализации.

Android → WSS/TLS → FastAPI на Pi → адаптеры STT → MT → TTS.
Ответы: события текста + аудиопоток. Локальная альтернатива: OnDeviceEngine.

## Клиент
app + core/audio, network, data, ui; feature/live, settings на первом этапе.
AudioRecord → проверка маршрута/ресемплинг → VAD → очередь с верхним пределом.
Воспроизведение: half-duplex по умолчанию, отменяемый TTS, аудиофокус.
UI: StateFlow/MVVM, состояния connecting/listening/translating/speaking/
reconnecting/offline/error. Кнопка остановки доступна всегда.
История Room только по настройке, секреты через Android Keystore, не обычный DataStore.

## Сервер
Разделение api/auth/licensing/pipeline/providers/storage.
ProviderCapabilities описывает язык, streaming, форматы и ограничения.
Секреты провайдеров только на сервере. Внешний HTTP API не обращается к произвольным
URL клиента. Тайм-ауты каждого этапа, bounded queues, отмена задач при stop/disconnect,
ограничения числа сессий на пользователя и общей нагрузки. Повтор платного запроса
только при понятной идемпотентности, без бесконечных ретраев.

## Данные
К таблицам ТЗ добавить otp_challenges (хэш кода, срок, число попыток),
refresh_sessions (хэши токенов, семейство ротации, отзыв), device_keys,
usage_ledger (уникальный ключ тарифицируемого события), provider_jobs,
audit_events без содержимого разговоров, consent_events и deletion_jobs.
Уникальные ключи: user+device installation; session+utterance index;
session+epoch+audio sequence. usage_daily — агрегат ledger, не единственный источник.
Аудиобуфер MVP только в RAM. Встречи — отдельная очередь и отдельный бюджет.
Серверную историю включать осознанно, с TTL и удалением производных данных.

## Размещение
Отдельный Compose и каталог данных на SSD, внутренние PostgreSQL/Redis без LAN-портов.
Первые испытания через Tailscale, пользовательский WSS-домен после проверки.
Readiness отделить от liveness; метрики задержки/ошибок/квот без текста и аудио.
Не устанавливать сервисы до завершения выбора провайдеров и проверки ресурсов Pi.

## Безопасность
OTP: одинаковые ответы для существующих/несуществующих аккаунтов, TTL, cooldown,
лимиты на аккаунт/IP, ограниченные попытки. Refresh rotation с reuse detection.
WS: тайм-аут авторизации, лимит кадра/скорости, проверка владельца session_id,
истечения лицензии и квот во время сессии, не только при подключении.
FAQ Markdown без сырого HTML и исполняемых ссылок. Пакеты: проверка размера, подписи,
хэша, доступного места; безопасная распаковка, атомарная установка.

## Совместимость с будущей продажей

Личный и коммерческий режимы используют один TranslationEngine и pipeline.
Проверка прав и учёт использования — отдельные интерфейсы, не условные проверки
оплаты внутри STT/MT/TTS. EntitlementPolicy личного режима не требует подписки;
коммерческая реализация сможет проверять тарифы и лицензии. BillingProvider
подключается позже. Не разворачивать коммерческую инфраструктуру в личном пилоте.

## Озвучка с настройками

По просьбе пользователя: системный TTS с выбором голоса, высоты тона и скорости,
предпрослушиванием и сохранением настроек для каждого языка, по образцу Massage Time.
Требования: [настройки озвучки](VOICE.md).
