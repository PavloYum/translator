# Дополнения к контракту v1 — проект, не реализован

> Актуализация 24.11.2026: пользователь выбрал личное использование.
> Коммерческие требования исходного ТЗ (OTP, подписки, лицензии, 72-часовой
> офлайн-доступ, платежи и тарифные квоты) не входят в личную версию.
> Для пилота: Tailscale и отзывной токен приложения; технические лимиты нагрузки
> и расходов API остаются. Разделы ниже о коммерческих механизмах сохранены
> как анализ исходного ТЗ, не как обязательства реализации.

Оригинальные REST endpoint и события сохранены в исходном ТЗ. До реализации
зафиксировать JSON Schema и OpenAPI вместе с контрактными тестами.

- Первое сообщение auth {protocol_version:1, access_token}; до него аудио запрещено.
  Тайм-аут 5 с. Не класть токены в URL/логи.
- start: server-created session_id для новой сессии; client_request_id для
  идемпотентности. mode, src, tgt валидируются по capabilities.
- ready: session_id, epoch, accepted_audio, limits, resume_until.
- Аудио: uint32 big-endian seq + pcm_s16le payload. При 100 мс payload 3200 байт.
  Нумерация внутри epoch. Размер и допустимый шаг описать явно. Не обрезать
  PCM посреди сэмпла; поддержать короткий завершающий кадр.
- ack: highest contiguous received seq означает приём в ограниченный RAM-буфер,
  а не завершение перевода/долговременное хранение. Отдельно processed_seq.
  ACK не реже 1 с (50 чанков по 100 мс = 5 с, слишком редкое подтверждение).
- resume: привязка к user/device, epoch, last_ack, last_received_event_id.
  Дубликаты кадров не отправлять провайдеру и не тарифицировать повторно.
  Если состояние потеряно — resume_unavailable и новая epoch с видимым пропуском.
- Текст: event_id, utterance_id, revision, final. Ревизии монотонны;
  повтор final идемпотентен, исправления оформляются отдельным событием.
- TTS: stream_id, utterance_id, encoding/rate/ch; каждый бинарный кадр содержит
  тип, stream_id и seq. Не смешивать потоки без маркировки. stop/cancel прерывает
  воспроизведение и генерацию. Старая epoch не воспроизводится после offline-switch.
- Конфликт 5/10 с: после 5 с предложить офлайн, после выбора отменить облачную
  обработку текущей непереданной реплики; буфер максимум 10 с до выбора/разрыва.
  Для уже принятых облаком реплик показать состояние, не озвучивать дважды.
- Backpressure: max_buffer_ms, pause/resume или явный overflow; никакого
  неограниченного накопления. Невосстановимую потерю кадров показать пользователю.
- ping/pong: heartbeat 15 с, дедлайн задаёт сервер. error содержит code,
  retryable, retry_after и безопасное сообщение; без содержимого чужих сессий.
- auth/refresh находится вне аудиопотока; смена access token через auth_update
  либо переподключение. Закрытие по квоте/лицензии освобождает все ресурсы.

REST: дополнить logout/revoke-device, курсорную выдачу встреч и их удаление,
job-status для обработки встречи, версии capability/manifest, идемпотентные
admin/payment операции. DELETE /me/data требует ясного объёма удаления:
история/аудио/производные данные отдельно от аккаунта и обязательного биллинга.
